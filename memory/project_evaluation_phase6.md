## 二、飞控可提供的 SLAM 相关数据

### 2.1 核心数据（直接用于 SLAM）

| 帧 | 字段 | 频率 | 用途 | 可靠性 |
|----|------|------|------|:-----:|
| 0x04 | 四元数 w,x,y,z | **200 Hz** | IMU 姿态 (roll/pitch/yaw) | ⭐⭐⭐ 高 |
| 0x01 | 角速度 gyr_x/y/z | **501 Hz** | IMU 角速度 | ⭐⭐⭐ 高 |
| 0x01 | 加速度 acc_x/y/z | **501 Hz** | IMU 线加速度 | ⭐⭐⭐ 高 |
| 0x07 | 速度 vel_x/y/z | 50 Hz | 里程计线速度 | ⭐⭐⭐ 高 |
| 0x05 | 融合高度 alt | 50 Hz | Z 轴位置约束 | ⭐⭐⭐ 高 |

### 2.2 辅助数据（增强 SLAM 鲁棒性）

| 帧 | 字段 | 频率 | 用途 | 可靠性 |
|----|------|------|------|:-----:|
| 0x08 | XY 位移 pos_x/y | 10 Hz | 里程计位置 | ⭐⭐ 中（需外部传感器） |
| 0x02 | 气压高度 baro | 50 Hz | 辅助高度 | ⭐⭐ 中 |
| 0x06 | 飞控模式/解锁 | 3.4 Hz | 状态监控 | ⭐⭐⭐ 高 |
| 0x0D | 电池电压/电流 | 5 Hz | 安全监控 | ⭐⭐⭐ 高 |

### 2.3 不可用数据

| 帧 | 原因 |
|----|------|
| 0x03 欧拉角 | 仅 2 Hz，不可用于实时控制 |
| 0x08 XY_Pos | 无 GPS/UWB/光流时数据不可靠 |

## 三、数据融合策略

### 3.1 核心原则

```
2D SLAM 本质是激光扫描匹配 → /scan 是主数据源
飞控 IMU 提供姿态先验 → 加速扫描匹配收敛
飞控速度提供运动先验 → 减少 odom 漂移
```

### 3.2 TF 树设计

```
map ──→ odom ──→ base_link ──→ laser_frame
 ↑        ↑          ↑             ↑
SLAM    飞控姿态    飞控速度    静态 TF
发布    四元数      (可选)      (已知偏移)
```

### 3.3 两种运行模式

**模式 A: 手持建图（dummy_odom）**
```
位置: 全零 (SLAM 自己估计)
姿态: 飞控 0x04 四元数
适用: 手持雷达，无 GPS
状态: dummy_odom_node.py 已实现 ✅
```

**模式 B: 飞控里程计（ano_bridge）**
```
位置: 飞控 0x08 XY_Pos + 0x05 高度
姿态: 飞控 0x04 四元数
速度: 飞控 0x07 Velocity
适用: 有外部定位(GPS/UWB)的飞行场景
状态: ano_bridge_node.py 已实现 ✅
```

### 3.4 关键帧优先级（给 slam-toolbox 的建议）

| 帧 | 在 SLAM 中的作用 | 建议频率 |
|----|-----------------|---------|
| `/scan` | 扫描匹配核心输入 | 10 Hz |
| `/imu` | 姿态先验 | 100 Hz（从 200Hz 降采样） |
| `/odom` | 运动先验 | 20 Hz |

## 四、后续阶段目标

### Phase 6.3 — 有线雷达验证 (优先级: P0)

**目标**: 确认 N10P 雷达在树莓派上正常工作，`/scan` 话题正常输出。

**输入**: N10P 雷达 → USB 串口 `/dev/ttyUSB0` @ 460800  
**输出**: `/scan` (LaserScan, 10Hz, frame_id=laser_frame)  
**验证**: `ros2 topic echo /scan` 看到距离数据

### Phase 6.4 — 飞控+雷达联合测试 (优先级: P0)

**目标**: 同时运行飞控桥接和雷达驱动，验证数据流完整。

**输入**: 
- 飞控 → `/dev/ttyAMA0` @ 500000 → `/odom` + `/imu`
- 雷达 → `/dev/ttyUSB0` @ 460800 → `/scan`

**验证**: 
- TF 树无冲突（odom→base_link→laser_frame）
- `/scan` 数据与 `/imu` 姿态一致
- 无资源竞争（内存 < 400MB）

### Phase 6.5 — SLAM 建图 (优先级: P0)

**目标**: 使用 slam-toolbox 完成手持建图。

**配置关键点**:
- 地图分辨率: 0.1m（树莓派内存约束）
- 求解器线程: 2（不超过 CPU 核数）
- 使用 `/imu` 提供姿态先验
- odom 用 dummy_odom（零位置 + 飞控姿态）

**验证**: 
- 生成 PGM 地图文件
- 地图与实际环境一致
- 无内存溢出

### Phase 6.6 — 建图质量对比 (优先级: P1)

**目标**: 对比 A/B 测试，量化飞控 IMU 对建图质量的提升。

| 测试组 | odom 姿态来源 | 预期 |
|--------|-------------|------|
| A 组 | 单位四元数（无飞控） | 旋转时地图变形 |
| B 组 | 飞控 0x04 四元数 | 旋转时地图稳定 |

**度量**: 闭合误差、地图重叠度

### Phase 6.7 — Nav2 导航 (优先级: P1)

**目标**: 基于 SLAM 地图实现自主导航。

**所需飞控数据**: 0x06 飞控模式（确认程控模式），电池监控

### Phase 6.8 — 性能调优与稳定化 (优先级: P1)

- QoS 参数调优（减少内存堆积）
- 串口重连机制增强
- 长时间运行稳定性测试（> 1 小时）

## 五、架构约束（不可违反）

1. **分层原则**: 协议层 → 传输层 → 应用层，每层独立可测
2. **零拷贝原则**: 回调中不复制大块数据，只更新引用
3. **故障隔离**: 飞控断线不导致雷达驱动崩溃，反之亦然
4. **内存红线**: 所有节点总内存 < 200MB（留给 SLAM 400MB）
5. **编译约束**: `colcon build --parallel-workers 2`
6. **进程清理**: 只 kill 自己的 PID，不用 pkill
